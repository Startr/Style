Every flexbox property.
No classes. No stylesheet.

Here's the whole trick: startr.style turns every CSS property into a custom property you write straight into the style attribute. The stylesheet reads your variable and applies the real thing. Any valid CSS value works. And the responsive suffixes (--jc-md, --fd-lg) give you mobile-first breakpoints inline — something class-based utilities can't pull off without a build step. Yes, the style attributes get long. We call that honesty.

the-entire-mental-model.html 
<!-- a flex container: column on phones, row from 768px up -->
<div style="--d:flex; --fd:column; --fd-md:row; --g:1rem; --ai-md:center;">

Why flexbox

Flexbox lets a container boss its children around: stretch them, squish them, reorder them, space them out, all without knowing how big any of them are yet. Block flow only goes down. Inline flow only goes across. Flexbox doesn't care, because one property flips a row into a column. Use it for components and anything that runs in a single line, and reach for grid (--d:grid, --gtc) when a layout needs rows and columns at once.

Why inline custom props

Two rules run this whole page. First, inline styles are the API: there's no cascade to manage and no classes to compose, so reuse lives in your templates and components. Second, values pass straight through to CSS, which means anything legal works, even --fb:clamp(12rem,30%,20rem). It also means a typo like --d:flax fails without a peep. Type carefully, and lint if you can. No compiler, no safety net. It is what it is.

1 · The two axes

Every flex layout runs along a main axis (the direction items flow, set by --fd) and a perpendicular cross axis. That's the whole vocabulary. --jc (justify-content) aligns along the main axis, and --ai (align-items) handles the cross. Go ahead, mash the buttons below. Each one is a single setProperty('--fd', …) call on the demo, because startr props are custom properties. You're not watching a simulation of the layout engine. You're poking the actual one.

Vocabulary

main axis — the flow direction. row ⇢ horizontal, column ⇣ vertical. *-reverse flips main-start and main-end.

cross axis — perpendicular to main. Where --ai, --as, and --ac operate.

main / cross size — an item's width or height, whichever lies along that axis. --fb sets the starting main size.

2 · Container props (the flex parent)

These go on the parent, and every one takes responsive suffixes. Nothing below is a screenshot: each box is styled with the exact props in its code block, and the buttons rewrite them live. Poke anything. A refresh puts it all back.

--d · display

The on switch. Set it and every direct child becomes a flex item. flex acts like a block, while inline-flex tucks into a line of text — the go-to for pill buttons and badges. 

style="--d:flex"          <!-- block-level container -->
style="--d:inline-flex"   <!-- flows inline, e.g. --d:inline-flex; --ai:center; --g:.5rem -->

--fw · flex-wrap

Left alone, flex items will crush themselves onto one line before they ever wrap (nowrap). Give them permission with wrap, or use wrap-reverse if you like your lines filled bottom-up. Heads up: startr has no flex-flow shorthand, so set --fd and --fw separately.

--jc · justify-content (main axis)

Decides what happens to leftover space on the main axis. space-between pins the first and last items to the edges. space-around gives every item its own equal side-spacing, which is why the middle gaps look doubled. And space-evenly is the perfectionist: every gap, edges included, comes out identical. When browser support matters most, stick to flex-start, flex-end, and center.

--ai · align-items (cross axis)

--jc's twin, working the cross axis. The default, stretch, pulls items to fill the container (min/max permitting). The sleeper hit is baseline: click it and watch item 3's oversized type snap into line with the others.

--ac · align-content

What --jc does for items, this does for whole lines on the cross axis. The catch is that it needs multiple lines to push around, so nothing happens until --fw:wrap (or wrap-reverse) actually produces some. Values mirror --jc, plus stretch. 

style="--d:flex; --fw:wrap;
       --ac:space-between; --h:300px;"

--g / --cg · gap

Space between items. The outer edges get nothing, so think of it as a minimum gutter — if space-between spreads things wider, the wider spacing wins. One value covers both directions, two values mean row column, and --cg targets column-gap alone. It even works in grid and multi-column. 

style="--g:1rem"          <!-- rows & columns -->
style="--g:.5rem 1.5rem"   <!-- row · column -->
style="--cg:2rem"         <!-- column-gap only -->

3 · Item props (the flex children)

These go on the children themselves. And a small mercy: float, clear, and vertical-align do nothing to a flex item, so those old fights are simply over.

--fg · flex-grow   --fs · flex-shrink   --fb · flex-basis

The big three. --fb is where an item starts: auto means "use my width/height", 0 means "pretend I have no content". --fg divides leftover space by share, so a --fg:2 item tries to grab twice what its --fg:1 siblings get. --fs is the same idea in reverse, deciding who shrinks when space runs out (default 1; negatives are invalid for both). --fx · flex (the recommended shorthand)

One prop that covers all three, filling in whatever you leave out with sensible answers. Prefer it over the individual props. A lone --fx:1 expands to grow:1 · shrink:1 · basis:0% — pure ratio sharing, content size ignored entirely. For the record, the CSS default is 0 1 auto. 

style="--fx:1"              <!-- equal columns, content ignored -->
style="--fx:none"           <!-- rigid: never grow, never shrink -->
style="--fx:1 1 240px"      <!-- fluid, but start from 240px -->
style="--fx:0 0 clamp(12rem,25vw,18rem)"  <!-- any CSS value works -->

--o · order

Everything starts at order:0 and renders in source order. Lower values jump ahead, and ties fall back to the HTML. The amber tile below is first in the markup, but --o:1 sends it to the back of the line. Careful, though: reordering is visual only. Keyboards and screen readers still follow the source.

4 · Responsive flexbox with suffixes

Stick -sm (≥640px), -md (≥768px), -lg (≥1024px), or -xl (≥1280px) on any responsive prop. Suffixes are mobile-first min-width queries: the bare prop is your phone layout, and each suffix kicks in from that width up. So write the phone version first, then add only the props that actually change at each step. Never repeat a base value in a suffix — it's just noise. 

<!-- phone: stacked · ≥768px: side-by-side, centered -->
<section style="
  --d:flex; --fd:column; --g:1rem;
  --fd-md:row; --ai-md:center;
  --jc-md:space-between; --g-md:2rem;
">

<!-- sidebar: full-width card on phone, fixed rail ≥1024px -->
<aside style="--fx:1 1 auto; --fx-lg:0 0 300px; --o:2; --o-lg:0;">

<!-- wrap on phone, single row from tablet up -->
<ul style="--d:flex; --fw:wrap; --fw-md:nowrap; --g:.5rem 1rem;">

7 · Footguns & fine print

A framework that hides its sharp edges just cuts you later. Here are ours, out in the open.

Typos fail silently

Misspell a prop and nothing happens. No error, no layout — --d:flax is just a variable nobody reads. If a prop "isn't working," check your spelling first, then confirm it exists in the utilities table.

Shared shorthands

Some props moonlight. --fs covers flex-shrink and font-style, while --td covers text-decoration and transition-delay. Pick one meaning per element; the same variable can't hold down two jobs at once.

--br is border-right now

Older startr markup used --br for border-radius. These days it means border-right, and rounding lives at --radius. Upgrading a legacy page? Hunt down every --br before it bites.

Inline styles are flat

There's no cascade or nesting to lean on. Hovers are covered by --hvr-c / --hvr-bgc / --hvr-bc, but :focus-visible and :active still need a small <style> block. Pair every hover with a focus style so keyboard users aren't left guessing. (This page does.)

Overriding from JS

Always el.style.setProperty('--d','none'), never el.style.display = 'none'. A direct assignment outranks every startr suffix, so one careless line of JS quietly kills your breakpoints for the rest of the page's life.

Desktop-first is the enemy

Suffixes are min-width queries, full stop. Start from a desktop layout and you'll spend all afternoon trying to walk it back down, because the framework only climbs. Your base is the phone. Everything above it is an upgrade.
